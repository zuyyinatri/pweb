Accessibility

Accessibility is about inclusivity: the site works for visual, hearing, mobility, cognitive, seizure, and speech needs. Open each principle.

PerceivableAlternative text, enough color contrast, less decorative content.
OperableEverything works with a keyboard; media can be controlled; touch screens work.
UnderstandableSimple wording, no useless elements, always notify the user.
RobustWorks with assistive tools and across browsers.

Name things for screen readers

<!-- Bad -->
<button>Kirim</button>
<button><i class="fa fa-heart"></i></button>

<!-- Good -->
<button>Bayar sekarang</button>
<button aria-label="Save as favorite">
  <i class="fa fa-heart"></i>
</button>
<img src="a.png" alt="Explanation">
<label for="tos">Do you agree?</label>

Use alt="" for purely decorative images. Use div with tabindex="0" only when a real button can’t do the job.

Media Capture and Stream API

The browser can reach the camera and microphone. The user is asked first, then you receive a MediaStream.

Camera demo

Press Start video and allow camera access.

The code

const stream = await navigator.mediaDevices
  .getUserMedia({ video: true });
video.srcObject = stream;
video.play();

// take a picture with Canvas
ctx.drawImage(video, 0, 0, width, height);
const data = canvas.toDataURL("image/png");

If the camera is blocked here, open the page in its own tab or run the code locally.

Service Worker and Notification

A service worker runs JavaScript on a background thread, as a proxy between your page and the web server. Step through its life cycle.

Life cycle

Notification permission

The user must agree first.

The code

await navigator.serviceWorker.register("./sw.js");

// sw.js
self.addEventListener("install", () => {});
self.addEventListener("activate", () => {});
self.addEventListener("push", (event) => {
  event.waitUntil(
    self.registration.showNotification("New todo!", {
      body: "Finish it before the deadline."
    })
  );
});
